# V9.1 — one production design system

Research checked 13 November 2026. The owner's OmniLearn nine-screen showcase remains the visual target: navy, orange primary actions, blue secondary actions, original logo/mascot and system typography. External public pages inform usability, not brand assets or exact compositions. No authenticated third-party workspace or unavailable recording was inspected.

| Reference and evidence | Existing problem | Production change | Proof |
| --- | --- | --- | --- |
| [Linear](https://linear.app/) exposes distinct workspace destinations and stresses reducing noise | Mixed text glyphs and a duplicate active-edge ornament compete with navigation labels | `product.js` uses independently drawn, consistent 18px SVG icons; `design-system.css` uses lighter labels and one active state | Main routes, drawer, focus and responsive assertions |
| [NotebookLM public help](https://support.google.com/notebooklm/answer/16164461) describes source-grounded chat with references | Home does not identify the material its existing chat engine will use | `dashboard-shell.js` shows the current source title, existing library selection route and reading action above the single composer | Source title matches actual active material; reading opens that source's chapter without inference |
| [Notion views, filters and sorts](https://www.notion.com/help/views-filters-and-sorts) organizes the same collection through multiple views | Catatan leads with raw text thumbnails, five competing buttons and a misleading empty-library message for failed searches | Topic-first cards, real text excerpts, metadata, pin indication, disclosure actions, content/subject search, result count and distinct no-match message; existing gallery/list and storage reused | Filter/search, both layouts across widths/themes, pin/rename/reload and source isolation |
| [Reader](https://readwise.io/read) emphasizes distraction-free reading of saved documents | Lesson prose and side controls have similar visual weight; reading typography lacks a shared measure | `study-workspace.css` caps prose at 68ch, uses 15px/1.8 leading, more paragraph spacing and local horizontal scrolling for tables/formulas | Reader typography and source-bound chapters; existing seven-tool responsive checks |
| [Khan Academy progress help](https://support.khanacademy.org/hc/en-us/articles/47078681852045-Where-can-I-view-my-skill-progress-in-Khan-Academy-Reimagined) connects recorded progress with next practice | Dashboard review action opens the last source even when another source owns the due cards | Existing scheduler selects a source with due cards; actual XP gap and current streak explain next steps | Unit regression for future/due/empty decks; browser click opens the due source with saved deck |
| [Geist typography](https://vercel.com/geist/typography) separates label and reading styles | Shared controls and reading copy lack explicit role tokens | Canonical CSS tokens for control height, labels, body, reading measure and leading; shared focus/reduced-motion retained | Both themes, seven widths, keyboard focus and reduced-motion checks |

These are independent OmniLearn implementations. No new framework, service, dependency, annotation system, duplicate store or invented mastery score. Existing source text, versions, chapters, originals, account scoping and Gemini/OCR remain intact. Excerpts are literal saved text, not claimed AI summaries.
